# 从 0.1 升级到 0.2

`0.2.0` 将活动架构从 Trellis 切换为模型无关的上下文与能力平面。这是破坏性升级，不提供
两套 Runtime 并行运行的兼容模式。

## 升级前

1. 记录平台仓库和每个待迁移项目的 Git 状态，包括未跟踪文件。
2. 备份机器所有的 Runtime `state/` 与本地配置；不要把凭据或项目源码放进平台仓库。
3. 在新投影和迁入知识完成复核前，保留项目原有 `.trellis/`。
4. 停止旧模型启动器或任务执行器。`0.2` 不恢复 Trellis workflow、hook、task、agent 或
   session 状态。

## 命令与路径变化

| `0.1` 接口 | `0.2` 接口 |
| --- | --- |
| `trellis-embedded-init` | `embedded-project init`、`refresh`、`doctor` |
| `trellis-branch` | `embedded-agent-branch` |
| `.trellis/spec/` | `.embedded-agent/rules/` 与 `.embedded-agent/context/` |
| `.trellis/knowledge/project/` | `.embedded-agent/knowledge/project/` |
| 面向 `$CODEX_HOME/bin` 的安装 | `~/.local/bin` 或 `EMBEDDED_PLATFORM_BIN_DIR` |
| Trellis Spec 安装目录 | Skill 使用 `EMBEDDED_PLATFORM_SKILL_DIR`；Rule Pack 投影到 `.embedded-agent/rules/platform/` |
| Jenkins `--server` / `--config` | 机器注册表与 `--connection-id` |
| 调用方指定 Aboot 工具/根目录 | 机器注册表与 `--connection-id` |
| 调用方指定 CAN DLL/backend | 机器所有的 driver registry |
| RTT `--reset --confirm` | `--reset --require-confirm --confirm` |
| `knowledge export --to` | `knowledge build --write` 与 `knowledge show` |
| `workspace remove` | 从公共 Runtime CLI 移除 |

Mac 与 WSL payload 不再选择 Runtime root 或 backend；先配置已安装的传输 Adapter，root 与
backend 由稳定的 Windows launcher 所有。SDK project/mapping 操作使用已登记项目工作区和
机器所有的 SDK store，不再接受调用方指定 workspace/root。

## 升级平台工具

### 保留已有 checkout 和本地能力改动

如果本地仍是旧私有仓库或存在未提交改动，先在独立目录获取新版源码。不要把不同历史的
公开仓库直接 `pull` 到旧分支，也不要用新版目录覆盖旧 checkout。

```bash
git clone https://github.com/dev1ce-g/embedded-agent-platform-public.git
cd embedded-agent-platform-public
git status --short --branch
git log -1 --oneline
```

对旧工作区逐项分类：Runtime 能力修正连同测试移植；机器路径和凭据转为机器配置；
项目规则与知识通过显式迁移保留；旧 workflow、task 与模型启动器不恢复。已部署的脚本
可能还有源码仓库之外的改动，应先比较实际部署文件，不能只依据仓库 HEAD 判断版本。

本地能力补丁应按新版接口适配，例如 Keil 工程/Target 和 library 输出支持不能因项目
名称不同而遗漏。先运行相应测试，再部署；不要直接将旧 Runtime 文件覆盖到新版安装。

### 先试装，再切换命令

macOS、Linux 或 WSL 可将新命令安装到独立目录，不立即修改默认 PATH：

```bash
EMBEDDED_PLATFORM_BIN_DIR="$HOME/.local/share/embedded-agent-platform/0.2.0/bin" \
EMBEDDED_PLATFORM_SKILL_DIR="$HOME/.local/share/embedded-agent-platform/0.2.0/skills" \
  ./install.sh
"$HOME/.local/share/embedded-agent-platform/0.2.0/bin/embedded-project" --version
```

此步骤只安装链接，不迁移项目、不升级 Windows Runtime，也不运行构建或设备操作。
模型适配使用这些 Skill 来源目录，不要求安装某个模型的启动器。

完成 Windows 端兼容检查与下文的项目迁移验收后，再选择默认命令目录。若原默认目录为空
或链接属于当前 checkout，可执行：

```bash
./install.sh
embedded-project --version
embedded-agent status --json
```

安装器只替换指向当前 checkout 受管目录的链接；指向另一个旧 checkout 的链接也会被
拒绝覆盖。使用 `command -v` 和 `ls -l` 核对实际入口，按本地备份策略处理已确认的旧链接，
或选择独立命令目录并显式调用。安装后的命令和 Skill 指向当前 checkout，因此需要保留它。

### Windows state 与连接配置

先从旧 Runtime 的 `status --json` 记录实际安装入口和 state 路径。旧部署的程序目录与
state 父目录可能不同；新版 launcher 默认使用安装根目录下的 `state/`，不是固定使用
`%LOCALAPPDATA%`。仅在原程序目录运行安装器，不会自动迁移另一个目录里的项目状态。

在无活动 Job 或设备操作时备份实际 state、机器配置及有本地修改的 Runtime 文件。选择
明确的安装 prefix；下例路径只是占位示例，应换成已核对的部署目录：

```powershell
py -3 runtime\windows\install.py --prefix C:\Tools\EmbeddedAgentPlatform
& 'C:\Tools\EmbeddedAgentPlatform\embedded-agent.cmd' status --json
```

安装器更新受管 Runtime 文件并保留目标 prefix 内的 `state/`，不复制外部旧 state，也不
保证旧 Job 可恢复。源 state 与目标不同时，先在隔离副本验证所需状态的兼容性，或重新
登记项目；不要合并两个在线 state。`EMBEDDED_AGENT_INSTALL_ROOT` 是机器启动配置，
不是任务参数；检查是否存在历史覆盖值，确保最终 `status` 与预期一致。

按需从示例创建安装根目录内的机器本地配置：

- `jenkins-connections.json` ← `jenkins-connections.example.json`；
- `aboot-connections.json` ← `aboot-connections.example.json`；
- `can-drivers.json` ← `can-runtime/can-drivers.example.json`。

真实 endpoint、路径或 credential reference 进入这些注册表后，不要将其提交到仓库。
配置 `EMBEDDED_AGENT_WORKSPACE_ROOT` 覆盖准备接入的工作区，重新检查项目登记、background
和 stale 状态。Aboot 配置见 [烧写说明](../operations/windows-agent-aboot-flash.md)；配置与
只读自检通过不构成真实烧写授权。

Mac/WSL Adapter 与 Windows Runtime 应一起切换到相同源码版本，再核对 `status` 中的
平台版本、contract 和源文件哈希。不要把旧 Runtime 的 `0.9.0` 命令版本当作新版平台
`0.2.0` 的版本比较结果；它们是不同的版本轴。

## 迁移每个项目

先预览，不写入：

```bash
embedded-project migrate-trellis /path/to/project --dry-run --json
```

再迁移数据、重建当前事实并验证投影：

```bash
embedded-project migrate-trellis /path/to/project --json
embedded-project init /path/to/project --discovery local --json
embedded-project doctor /path/to/project --json
embedded-project refresh /path/to/project --discovery local --json
embedded-project doctor /path/to/project --json
```

如果权威工具链事实只存在于已登记的 Windows workspace，改用 Windows Discovery。手动审查
所有 `*.trellis.new` 冲突候选。完整数据映射见
[从 Trellis 迁移](from-trellis.md)。

## 验收与清理

删除旧状态前，确认：

- `doctor` 成功；
- `.embedded-agent/manifest.json`、平台规则和生成上下文存在；
- 项目规则与知识仍可审查、可选择纳入版本控制；
- 项目未变化时，重复 `refresh` 的结果稳定；
- Agent 使用 `AGENTS.md`、`.embedded-agent/` 与固定 Runtime 命令，不再读取旧 workflow 或
  task 状态。

删除 `.trellis/` 是项目所有者的独立决定。平台不提供双向同步，也不支持 `0.1`/`0.2` 混合
执行。需要回退时，先还原备份的 Runtime state/config 与旧平台 checkout，再启动旧 runner；
不要让两个版本同时指向可变的在线状态。
