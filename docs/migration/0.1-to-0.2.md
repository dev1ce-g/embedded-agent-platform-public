# Upgrading From 0.1 To 0.2

Version `0.2.0` replaces the active Trellis architecture with a
model-independent context and capability plane. This is a breaking upgrade,
not a dual-runtime compatibility release.

## Before Upgrading

1. Record the Git status of the platform checkout and every project being
   migrated, including untracked files.
2. Back up machine-owned Runtime state and configuration. Do not put credentials
   or project source in the platform repository.
3. Keep each project's `.trellis/` directory until the new projection and
   imported knowledge have been reviewed.
4. Stop any old model launcher or task runner. Version `0.2` does not resume
   Trellis workflow, hook, task, agent, or session state.

## Command And Path Changes

| `0.1` surface | `0.2` surface |
| --- | --- |
| `trellis-embedded-init` | `embedded-project init`, `refresh`, and `doctor` |
| `trellis-branch` | `embedded-agent-branch` |
| `.trellis/spec/` | `.embedded-agent/rules/` and `.embedded-agent/context/` |
| `.trellis/knowledge/project/` | `.embedded-agent/knowledge/project/` |
| `$CODEX_HOME/bin`-oriented install | `~/.local/bin` or `EMBEDDED_PLATFORM_BIN_DIR` |
| Trellis Spec install directory | `EMBEDDED_PLATFORM_SKILL_DIR` for Skills; Rule Packs project into `.embedded-agent/rules/platform/` |
| Jenkins `--server` / `--config` | machine-owned registry plus `--connection-id` |
| Aboot caller-selected tool/root | machine-owned registry plus `--connection-id` |
| CAN caller-selected DLL/backend | machine-owned driver registry |
| RTT `--reset --confirm` | `--reset --require-confirm --confirm` |
| `knowledge export --to` | `knowledge build --write` and `knowledge show` |
| `workspace remove` | removed from the public Runtime CLI |

Mac and WSL payloads no longer select the Runtime root or backend. Configure the
installed transport, then let the stable Windows launcher own those values.
SDK project and mapping operations use the registered project workspace and
machine-owned SDK store; caller-selected workspace/root overrides are removed.

## Upgrade The Platform Tools

### Preserve Existing Checkouts And Capability Patches

If the local checkout still uses an older private history or contains local
changes, clone the public source into a separate directory. Do not pull an
unrelated history into the old branch or overwrite that checkout.

```bash
git clone https://github.com/dev1ce-g/embedded-agent-platform-public.git
cd embedded-agent-platform-public
git status --short --branch
git log -1 --oneline
```

Port reusable Runtime fixes with their tests; move machine paths and credentials
to local configuration; migrate project rules and knowledge explicitly. Do not
restore old workflows, tasks, or model launchers. Compare deployed files too:
a checkout HEAD does not identify locally patched deployment files. Adapt
capability patches such as Keil project/Target selection and library outputs to
the new interface instead of copying old Runtime files over the new installation.

### Stage Before Switching Commands

On macOS, Linux, or WSL, install into an isolated directory without changing the
default PATH:

```bash
EMBEDDED_PLATFORM_BIN_DIR="$HOME/.local/share/embedded-agent-platform/0.2.0/bin" \
EMBEDDED_PLATFORM_SKILL_DIR="$HOME/.local/share/embedded-agent-platform/0.2.0/skills" \
  ./install.sh
"$HOME/.local/share/embedded-agent-platform/0.2.0/bin/embedded-project" --version
```

This installs links only. It does not migrate projects, upgrade Windows, build,
or access devices. After Windows compatibility checks and project acceptance,
select the default command directory. If it is empty or managed by this checkout:

```bash
./install.sh
embedded-project --version
embedded-agent status --json
```

The installer only replaces links targeting managed directories in the current
checkout. Links to another checkout are also rejected. Inspect `command -v`
and `ls -l`; back up and handle confirmed old links separately, or keep an
isolated command directory. Keep the checkout in place because commands and
Skills link to it. No model-specific launcher is required.

### Windows State And Connections

Record the old installed entry point and actual state path from `status --json`.
Older deployments may keep programs and state under different parents. The new
launcher defaults to `<install-root>\\state`, not a fixed `%LOCALAPPDATA%` path.
Reinstalling into the old program directory does not migrate state from elsewhere.

With no active jobs or device operations, back up the actual state, machine
configuration, and locally modified Runtime files. Select an explicit prefix;
replace the example below with the verified deployment directory:

```powershell
py -3 runtime\windows\install.py --prefix C:\Tools\EmbeddedAgentPlatform
& 'C:\Tools\EmbeddedAgentPlatform\embedded-agent.cmd' status --json
```

The installer preserves state already inside the destination prefix. It does
not copy external state or guarantee old jobs can resume. Validate required
state on an isolated copy or register projects again; never merge two live
state stores. Inspect any machine-level `EMBEDDED_AGENT_INSTALL_ROOT` override
and confirm the resulting paths with `status`. Transport payloads cannot set it.

Create local machine-owned registries in the installation root as needed:

- `jenkins-connections.json` from `jenkins-connections.example.json`;
- `aboot-connections.json` from `aboot-connections.example.json`;
- `can-drivers.json` from
  `can-runtime/can-drivers.example.json`.

Do not commit these local registries when they contain real endpoints, paths,
or credential references.

Set `EMBEDDED_AGENT_WORKSPACE_ROOT` to cover the intended workspaces, then check
project registration, background, and staleness. See the
[Aboot runbook](../operations/windows-agent-aboot-flash.md) for the new connection
configuration. Read-only checks are not authorization to flash hardware.

Switch Mac/WSL adapters and Windows Runtime to the same source version together;
verify platform version, contract, and source hashes from `status`. A legacy
Runtime command version `0.9.0` and platform version `0.2.0` are different version
axes, not directly comparable release numbers.

## Migrate Each Project

Preview the copy plan before any write:

```bash
embedded-project migrate-trellis /path/to/project --dry-run --json
```

Then migrate data, regenerate current facts, and validate the projection:

```bash
embedded-project migrate-trellis /path/to/project --json
embedded-project init /path/to/project --discovery local --json
embedded-project doctor /path/to/project --json
embedded-project refresh /path/to/project --discovery local --json
embedded-project doctor /path/to/project --json
```

Use Windows discovery when the canonical toolchain facts exist only in the
registered Windows workspace. Review any `*.trellis.new` conflict candidate
manually. The complete data mapping is in
[Migrating From Trellis](from-trellis.md).

## Acceptance And Cleanup

Before removing any old state, confirm that:

- `doctor` succeeds;
- `.embedded-agent/manifest.json`, platform rules, and generated context exist;
- project-owned rules and knowledge remain reviewable and can be versioned;
- repeated `refresh` is stable for an unchanged project;
- agents use `AGENTS.md`, `.embedded-agent/`, and fixed Runtime commands rather
  than old workflow or task state.

Deletion of `.trellis/` is a separate project-owner decision. There is no
bidirectional synchronization or supported mixed `0.1`/`0.2` execution mode.
To roll back, restore the backed-up Runtime state/configuration and the prior
platform checkout before restarting an old runner; do not point both versions
at live mutable state simultaneously.
